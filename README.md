# 🎯 سیستم مدیریت KPI (KPI Management System)

یک سیستم کامل و **محلی** برای مدیریت عملکرد و ارزیابی KPI کارمندان، ساخته‌شده با **React/Next.js**، **Python/FastAPI** و **SQLite** — بدون وابستگی به سرویس‌های ابری، قابل اجرا با **Docker**.

- **فرانت‌اند:** Next.js (React 19) — پورت پیش‌فرض `8003`
- **بک‌اند:** FastAPI — پورت پیش‌فرض `8000`
- **دیتابیس:** SQLite (حالت WAL) — مناسب تا ~۵۰ نفر
- **احراز هویت:** JWT + چهار نقش (مدیر سیستم، مدیر منابع انسانی، مدیر تیم، کارمند)
- **لایسنس:** [MIT](LICENSE)
- **نسخه فعلی:** `v1.12.0` — [تاریخچه کامل نسخه‌ها](#تاریخچه-نسخهها)
- **انتشار:** [راهنمای کامل Release](PUBLISHING.md)

## امکانات

| بخش | قابلیت‌ها |
|------|-----------|
| 👥 **مدیریت کارمندان** | افزودن، ویرایش، حذف، **انتقال بین تیم‌ها**، **آرشیو** (مخفی از نمای فعال)، **ورود گروهی** (اکسل یا JSON)، **جستجوی فوری** (کد پرسنلی، نام، سمت، تیم، تلفن) |
| 🏢 **مدیریت تیم‌ها** | ساخت تیم، افزودن/حذف عضو، مشاهده اعضا، **جستجوی فوری تیم و اعضا** |
| 📊 **امتیازدهی KPI** | ورود دستی نمره (۰-۱۰۰) برای هر معیار + **خروجی/ورودی اکسل** (دانلود فرم، آپدیت نمره‌ها) |
| ⚖️ **پیکربندی KPI** | معیارهای مشترک و تخصصی، وزن‌دهی به تفکیک تیم، **ترکیب نمره نهایی** (نمره مدیر + ارزیابی ۳۶۰ + اهداف) |
| 📅 **دوره‌های گزارش‌گیری** | ساخت دوره (ماهانه/فصلی/…)، فعال‌سازی، **آرشیو خودکار** دوره‌های بیش از ۳ ماه |
| 🧮 **موتور محاسبه KPI** | میانگین وزنی + ترکیب با ارزیابی همکاران و تحقق اهداف؛ نتایج کش‌شده و قابل محاسبه مجدد |
| 📈 **داشبورد منابع انسانی** | نرخ ترک خدمت، توزیع نمرات، رتبه‌بندی تیم‌ها، روند دوره‌ها، برترین‌ها، **فاصله خودارزیابی/مدیر**، **هشدار افت متوالی**، **نرخ غیبت**، **تحقق اهداف**، **اسپارک‌لاین روند تیم‌ها**، ساعت و تاریخ شمسی زنده |
| 📊 **گزارش‌ها** | گزارش تیمی و فردی، نمودار روند (Recharts)، **چاپ/PDF**، **خروجی PDF سمت سرور با فونت فارسی**، **مقایسه دو دوره کنار هم** |
| 🔔 **اعلان‌ها** | زنگ اعلان با نشانگر، یادآوری مهلت دوره‌ها، صفحه کامل اعلان‌ها |
| 🎯 **اهداف (OKR-lite)** | تعریف هدف کمی برای هر کارمند، پیگیری پیشرفت، درصد تحقق |
| ◬ **ارزیابی ۳۶۰** | هم‌تیمی‌ها به یکدیگر در همکاری/ارتباطات/قابلیت اطمینان نمره می‌دهند |
| 🪞 **خودارزیابی** | کارمند نمره خود را ثبت می‌کند؛ مقایسه با نمره مدیر در گزارش |
| 🎯 **طرح بهبود (PIP)** | تشخیص خودکار افت متوالی، ایجاد طرح بهبود با وضعیت‌پذیری |
| 📅 **غیبت‌ها** | ثبت روزهای غیبت، نرخ غیبت سال جاری، تفکیک تیمی |
| 📋 **گزارش سفارشی** | فیلتر بر اساس تیم/بازه/معیار/بازه نمره |
| 💾 **پشتیبان‌گیری** | دانلود نسخه پشتیبان SQLite + بازیابی از فایل + **پشتیبان خودکار شبانه با نگهداری ۳۰ روزه** |
| 🔍 **جستجوی سراسری** | جستجوی فوری در همه لیست‌ها (کارمند با کد/نام/سمت/تیم، تیم با بخشی از نام، کاربر با نام/نقش) با نرمال‌سازی حروف فارسی و ارقام |
| 🔐 **امنیت** | JWT با انقضای ۱۲ ساعته، bcrypt، قفل ورود بعد از تلاش‌های ناموفق، تغییر اجباری رمز اولیه |
| 📋 **جدول‌های پیشرفته** | مرتب‌سازی با کلیک روی ستون، هدر چسبان، دکمه‌های عملیات هنگام hover، کارت‌های موبایل |
| 📜 **گزارش فعالیت (Audit)** | ثبت خودکار تغییرات (کارمند، نمره، پیکربندی، ورود گروهی) برای انطباق HR |

> **سطوح دسترسی:** هر نقش فقط منوها و داده‌های مرتبط با خودش را می‌بیند — این محدودیت هم در منوی فرانت‌اند و هم روی تمام endpointهای بک‌اند اعمال می‌شود. مدیر تیم فقط به اعضای تیم خودش امتیاز می‌دهد، کارمند فقط پرونده خودش را می‌بیند، و ارزیابی ۳۶۰ فقط بین هم‌تیمی‌هاست.

### حساب‌های پیش‌فرض

| کاربر | رمز | نقش |
|-------|-----|-----|
| `admin` | `admin123` | مدیر سیستم |

## شروع سریع (Docker)

```bash
docker compose up --build -d

# دسترسی:
# فرانت‌اند: http://localhost:3000
# مستندات API: http://localhost:8000/docs
# سلامت:      http://localhost:8000/health
```

### دستورات Docker

```bash
docker compose up --build   # اجرا و ساخت
docker compose up -d        # اجرا در پس‌زمینه
docker compose down         # توقف
docker compose logs -f backend   # لاگ بک‌اند
docker compose logs -f frontend  # لاگ فرانت‌اند
```

**داده‌های SQLite** در حجم `db-data` (مپ‌شده به `/app/data` در کانتینر) نگهداری می‌شوند و با `docker compose down` از بین نمی‌روند. دادهٔ نمونه (تیم‌ها، معیارها و کارمندان) به‌صورت خودکار هنگام اولین اجرا seed می‌شود؛ برای شروع از نو، حجم را حذف کنید: `docker volume rm kpi-calc_db-data`.

### انتشار به GitHub و Docker Hub

اسکریپت `release.sh` همهٔ مراحل (ساخت ریپو، push و تگ‌زدن ایمیج‌ها) را یکجا انجام می‌دهد:

```bash
bash release.sh           # پیش‌فرض: نسخهٔ v1.0.1
bash release.sh v1.1.0    # با نسخهٔ دلخواه
```

قبل از اجرا، یک‌بار وارد حساب‌های خود شوید:

```bash
docker login -u meysam8498        # داکر هاب
gh auth login                      # گیت‌هاب (یا یک Personal Access Token)
```

پس از آن، ایمیج‌ها با نام‌های زیر روی Docker Hub می‌نشینند:

```
meysam8498/hr-kpi-platform:backend-<نسخه>
meysam8498/hr-kpi-platform:frontend-<نسخه>
meysam8498/hr-kpi-platform:backend-latest
meysam8498/hr-kpi-platform:frontend-latest
```

## معماری و جریان داده

```
┌─────────────────────────────────────────────┐
│                 Browser                      │
│  ┌────────────────────────────────────────┐  │
│  │       Next.js Frontend (React)         │  │
│  │   http://localhost:8003 (dev)          │  │
│  └──────────────┬─────────────────────────┘  │
│                 │ /api/*                     │
│  ┌──────────────▼─────────────────────────┐  │
│  │       FastAPI Backend (Python)         │  │
│  │   http://localhost:8000                │  │
│  └──────────────┬─────────────────────────┘  │
│                 │                             │
│  ┌──────────────▼─────────────────────────┐  │
│  │          SQLite Database               │  │
│  │   kpi_system.db (WAL mode)            │  │
│  └────────────────────────────────────────┘  │
└─────────────────────────────────────────────┘
```

**تصمیم‌های کلیدی طراحی:**

- **صفر وابستگی ابری** — همه‌چیز به‌صورت محلی اجرا می‌شود.
- **SQLite با WAL** — سبک، خواندن همزمان، مناسب برای ≤۵۰ کاربر.
- **پیکربندی‌محور** — معیارها، وزن‌ها، دوره‌ها و ترکیب نمره در دیتابیس ذخیره می‌شوند، نه در کد.
- **تک‌ادمین بدون احراز هویت** — ساده‌ترین حالت برای ابزار داخلی.

### جریان داده

1. **ادمین** پیکربندی می‌کند: تیم‌ها، معیارهای KPI (مشترک/تخصصی)، وزن‌دهی هر تیم، دوره‌های گزارش‌گیری، و **ترکیب نمره نهایی**.
2. **نمره‌دهی:** از طریق فرم دستی یا **اکسل** (دانلود فرم ← پر کردن ← آپلود) برای هر کارمند در هر دوره ثبت می‌شود.
3. **موتور KPI** محاسبه می‌کند:
   - نمره پایه = میانگین وزنی معیارها.
   - نمره نهایی = ترکیبِ نمره پایه + ارزیابی ۳۶۰ + تحقق اهداف با وزن‌های هر تیم.
   - نتیجه با جزئیات کامل کش می‌شود (مجددا قابل محاسبه است).
4. **گزارش‌ها** نمایش می‌دهند: تاریخچه فردی، میانگین تیمی، نمای کل شرکت، و داشبورد منابع انسانی.

## مرجع API

**Base URL:** `http://localhost:8000` — همه‌ی endpoint ها (به‌جز `/api/auth/login`) نیازمند هدر `Authorization: Bearer <token>` هستند و دسترسی نقش‌محور دارند:

| نقش | دسترسی |
|-----|--------|
| **admin** | همه‌چیز + مدیریت کاربران + پشتیبان‌گیری |
| **hr** | همه داده‌ها و گزارش‌ها، دوره‌ها و امتیازدهی — بدون مدیریت کاربران/پشتیبان‌گیری |
| **manager** | فقط تیم خودش: امتیازدهی، گزارش تیمی، اهداف و غیبت اعضای تیم |
| **employee** | فقط پرونده خودش: خودارزیابی، اهداف خودش، گزارش خودش |

## فرمول محاسبه KPI

### نمره پایه — میانگین وزنی

```
Base Score = Σ(score_i × weight_i) / Σ(weight_i)
```

- `score_i` = نمره مدیر برای معیار i (۰-۱۰۰)
- `weight_i` = وزن اهمیت معیار i (به تفکیک تیم)

### نمره نهایی — ترکیب (Blend)

```
Final Score = (Base×base_w + Peer×peer_w + Goal×goal_w) / (base_w + peer_w + goal_w)
```

| مؤلفه | توضیح | وزن پیش‌فرض |
|-------|-------|-------------|
| **نمره مدیر (KPI)** | میانگین وزنی معیارها | ۷۰٪ |
| **ارزیابی ۳۶۰ (همکاران)** | میانگین سه بعد همکاری/ارتباطات/قابلیت اطمینان | ۱۵٪ |
| **تحقق اهداف** | میانگین درصد تحقق اهداف دوره | ۱۵٪ |

**قواعد:**
- وزن‌ها **به تفکیک تیم** در «تنظیمات KPI → ترکیب نمره نهایی» قابل تنظیم‌اند و هنگام ذخیره خودکار به ۱۰۰٪ نرمال می‌شوند.
- فقط مؤلفه‌هایی که داده دارند در محاسبه وارد می‌شوند (اگر کارمندی ارزیابی ۳۶۰ و هدف نداشته باشد، نمره‌اش با نرمال‌سازی وزن‌های موجود محاسبه می‌شود تا به‌طور مصنوعی پایین نیاید).

### مثال

**علی رضایی — تیم نرم‌افزار** (وزن‌ها: پایه ۰.۷، ۳۶۰ ۰.۱۵، اهداف ۰.۱۵)

| مؤلفه | نمره | وزن | سهم |
|-------|------|-----|-----|
| نمره مدیر (KPI) | ۸۸.۴ | ۰.۷ | ۶۱.۸۸ |
| ارزیابی ۳۶۰ | ۹۰.۰ | ۰.۱۵ | ۱۳.۵۰ |
| تحقق اهداف | ۹۶.۴۳٪ | ۰.۱۵ | ۱۴.۴۶ |
| **نمره نهایی** | | | **۸۹.۸۴** |

#### منابع

- Kaplan, R.S. & Norton, D.P. (1996). *The Balanced Scorecard*. Harvard Business School Press.
- Armstrong, M. & Taylor, S. (2020). *Armstrong's Handbook of HRM Practice*. Kogan Page.
- SHRM. Best Practices in Performance Management.

## راهنمای پیکربندی KPI

### معیارهای پیش‌فرض

**مشترک (همه تیم‌ها):** حضور و غیاب، مهارت‌های ارتباطی، همکاری تیمی، حل مسئله، انعطاف‌پذیری.

**تخصصی (مثال‌ها):** کیفیت کد، سرعت تحویل، نوآوری فنی (نرم‌افزار/زیرساخت)؛ دستیابی به هدف فروش، روابط با مشتری (فروش)؛ رعایت فرآیندها (HR)؛ دقت مالی (مالی).

### افزودن معیار جدید
1. به **⚙️ تنظیمات KPI** بروید.
2. در «معیارهای KPI» → «+ معیار جدید» نام، توضیح و دسته (مشترک/تخصصی) را وارد کنید.
3. «ذخیره» را بزنید.

### تغییر وزن‌دهی هر تیم
1. در «وزن‌دهی معیارها» تیم را انتخاب کنید.
2. معیار و وزن درصد را اضافه یا حذف کنید (مجموع = ۱۰۰٪ توصیه می‌شود).

### تنظیم ترکیب نمره نهایی
1. در «🧬 ترکیب نمره نهایی» تیم را انتخاب کنید.
2. سه وزن (نمره مدیر / ارزیابی ۳۶۰ / تحقق اهداف) را به درصد تنظیم کنید.
3. «ذخیره ترکیب» — وزن‌ها به‌صورت خودکار نرمال می‌شوند و تغییر در لاگ فعالیت ثبت می‌شود.

### ساخت دوره گزارش‌گیری
1. به **📅 دوره‌ها** بروید.
2. نام، نوع (ماهانه/فصلی/…)، تاریخ شروع و پایان را وارد کنید.
3. «ایجاد» — دوره فعال می‌شود و می‌توان برای آن نمره‌دهی کرد. دوره‌های بیش از ۳ ماه از پایان، خودکار آرشیو می‌شوند.

## تست

### بک‌اند

```bash
cd backend
pip install pytest httpx
python -m pytest tests/ -v
```

تست‌ها شامل:
- **موتور KPI**: فرمول میانگین وزنی، ترکیب با ارزیابی ۳۶۰ و اهداف، نرمال‌سازی وزن‌ها، موارد مرزی
- **API**: CRUD کارمند، انتقال/آرشیو، ورود گروهی، تنظیم ترکیب نمره، لاگ فعالیت، پشتیبان‌گیری
- **سطوح دسترسی**: مسدود شدن عملیات مدیریتی برای نقش‌های غیرمجاز

### CI

هر push به گیت‌هاب به‌صورت خودکار این‌ها را اجرا می‌کند (`.github/workflows/ci.yml`):
- بک‌اند: `pytest` روی Python 3.12
- فرانت‌اند: `tsc --noEmit` + build

### مهاجرت دیتابیس (Alembic)

```bash
cd backend
python -m alembic current            # نسخه فعلی
python -m alembic upgrade head       # اعمال مهاجرت‌ها
python -m alembic revision --autogenerate -m "توضیح"  # ساخت مهاجرت جدید
```

کانتینر بک‌اند هنگام هر استارت، خودکار `alembic upgrade head` را اجرا می‌کند.

### پشتیبان‌گیری خودکار شبانه

بک‌اند هر ۲۴ ساعت یک snapshot از دیتابیس SQLite در `backend/backups/` می‌گیرد و ۳۰ نسخه آخر را نگه می‌دارد. بازیابی دستی از صفحه «پشتیبان‌گیری» انجام می‌شود.
